# AGENTS.md — инструкции для ИИ-агентов проекта

Этот файл — общий контекст и правила для всех ИИ-агентов, работающих в репозитории
(Codex, OpenCode, Claude Code, Qwen Code, Gemini CLI и др.). Инструменты, которые
не читают `AGENTS.md` автоматически, подключают его через свои файлы памяти
(`CLAUDE.md`, `QWEN.md`, `GEMINI.md` — см. ниже «Настройка по инструментам»).

## Контекст проекта

**AI-агент для бэк-офиса брокера.** Агент помогает сотруднику разбирать неоднозначные
расхождения после сверки сделок: сопоставлять запись об исполнении заявки, операцию
по счёту и клиринговые выписки, находить корректировки, сверяться с регламентом.

Агент встраивается в **карточку расхождения**:
1. собирает хронологию по записям (исполнение заявки, операция по счёту, клиринговая выписка);
2. показывает возможную причину расхождения со ссылками на записи (например, комментарий о корректировке);
3. предлагает, что проверить дальше: дождаться следующей выгрузки, запросить недостающую запись или передать случай на исправление.

Решение принимает сотрудник; цель — сократить время до обоснованного решения.
Пример: в заявке исполнено 100 акций, в клиринговой выписке отражено 90 — агент
показывает комментарий о корректировке и предлагает проверить следующую выгрузку.

## Общие правила для всех агентов

1. Язык ответов и документации — русский (идентификаторы кода — английский).
2. Перед началом работы изучи репозиторий: `docs/` и существующий код.
3. Артефакты складывай в структуру ниже, не сваливай всё в корень.
4. Не додумывай вводные: недостающие данные фиксируй как открытые вопросы.
5. Ключевые решения фиксируй письменно (план, ADR), а не только в переписке.
6. Если заблокирован — честно опиши блокер, не имитируй прогресс.

## Структура артефактов

```
docs/
  research/      — ресерч: YYYY-MM-DD-<тема>.md
  requirements/  — требования, user stories, глоссарий (бизнес-аналитик)
  architecture/  — обзор архитектуры, датамодель, контракты (архитектор)
  adr/           — архитектурные решения: NNNN-<решение>.md
  plans/         — планы и статусы работы (директор)
  reports/       — тест-планы и отчёты о прогоне (тестировщик)
agents/roles/    — каноничные промпты ролей (источник правды)
.agents/         — субагенты для Freebuff / Codebuff (TS AgentDefinition)
```

## Роли (субагенты)

Полный промпт каждой роли существует **в одном экземпляре** — `agents/roles/<роль>.md`.
Файлы субагентов для конкретных инструментов (`.opencode/agents/`, `.claude/agents/`,
`.qwen/agents/`, `.agents/`) — тонкие обёртки: только настройки инструмента (права,
модели, списки инструментов) и отсылка к файлу роли. Субагент читает своё ТЗ из
`agents/roles/` при старте, поэтому все роли имеют инструменты чтения файлов.

Правки:
- текст роли — только в `agents/roles/<роль>.md`, перегенерация не нужна;
- права, модели и списки инструментов роли — в `scripts/generate-agents.py`,
  затем `python3 scripts/generate-agents.py`.

| Роль | ID | Зона ответственности |
| --- | --- | --- |
| Директор | `director` | Декомпозиция задач, план, назначение субагентов, приёмка результатов, эскалация |
| Ресерчер темы | `researcher` | Веб-исследование: рынок, аналоги, технологии, регуляторика; отчёт с источниками |
| Бизнес-аналитик | `business-analyst` | Требования, user stories с критериями приёмки, процессы, глоссарий домена |
| Архитектор | `architect` | Компоненты, датамодель, API-контракты, ADR, trade-offs |
| Программист | `developer` | Реализация кода по архитектуре, тесты, прогон линтеров |
| Тестировщик | `tester` | Тест-план, тест-кейсы, автотесты, отчёты о дефектах, вердикт о готовности |

### Регенерация

```sh
python3 scripts/generate-agents.py          # перегенерировать субагентов
python3 scripts/generate-agents.py --check  # проверить актуальность (CI)
```
